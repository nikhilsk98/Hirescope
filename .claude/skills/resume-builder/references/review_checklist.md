# Reviewer checklist (hiring-manager view)

Used by the reviewer pass (`review_packet.md` repeats it with the draft's rule findings).

- Relevance: each bullet earns its place for this job; strongest evidence for the required skills first.
- Clarity: what was built, with what, and the result, in one read.
- Repetition: same idea, verb or keyword repeated (keywords at most ~3 times).
- Weak bullets: vague scope, no technology, no outcome, weak openers ("Responsible for", "Worked on", "Helped"),
  filler ("solving the … problem by", "leveraged", "various").
- Defensibility: every word explainable in an interview; no ownership (led, managed, owned, spearheaded) or scale
  (large-scale, millions, enterprise) the evidence doesn't state; numbers exactly as written.
- Keywords: JD wording only where the evidence supports it; AWS ≠ GCP, MySQL ≠ PostgreSQL.
- Skills consistent with the bullets; no skill without evidence.
- US norms: no photo, age, marital status, nationality or visa status; past tense for past roles; uniform dates.
